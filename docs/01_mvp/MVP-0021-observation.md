# MVP-0021 Observation

## 목적

MVP-0020 Observation의 "범위 밖"에 남긴 항목("GOAL_MARKERS의 나머지
항목('해야 한다'/'검토가 필요'/'확인이 필요')의 부정형 점검 — 이번에
실측하지 않았다")을 실측·수정한다. 같은 조사 과정에서
QUESTION_MARKERS가 `"검토가 필요"`/`"확인이 필요"`를 GOAL_MARKERS와
공유하고, 추가로 `"판단이 필요"`를 갖는다는 사실을 확인해 함께
다뤘다. 새 메커니즘 없이 기존 `NEGATED_MARKER_EXCEPTIONS`/
`_contains_marker`(MVP-0018) 구조만 재사용했다.

## 발견한 문제 (실제 실행으로 확인)

| 마커 | 오탐 문장 | 수정 전 결과 |
|---|---|---|
| GOAL `검토가 필요` | "이 항목은 검토가 필요 없다." | Goal로 잘못 뽑힘 |
| GOAL `확인이 필요` | "이 항목은 확인이 필요 없다." | Goal로 잘못 뽑힘 |
| QUESTION `검토가 필요` | "이 항목은 검토가 필요 없다." | Open Question으로 잘못 뽑힘 |
| QUESTION `확인이 필요` | "이 항목은 확인이 필요 없다." | Open Question으로 잘못 뽑힘 |
| QUESTION `판단이 필요` | "이 항목은 판단이 필요 없다." | Open Question으로 잘못 뽑힘 |

`"검토가 필요"`/`"확인이 필요"`는 GOAL_MARKERS와 QUESTION_MARKERS가
동일한 문자열을 공유하므로, `NEGATED_MARKER_EXCEPTIONS`에 마커별로
한 번만 등록하면 두 목록 모두에 적용된다(`_contains_marker`가 목록과
무관하게 마커 문자열 자체로 조회하기 때문).

**"해야 한다"는 재현되지 않았다.** `"하지 않아야 한다"`로 시도했으나
`"해야 한다"`와 어간이 달라(`"않아야 한다"` vs `"해야 한다"`) 부분
문자열로 걸리지 않았다 — 실제 오탐이 없으므로 등록하지 않았다.

## 관찰 결과

### 5건 모두 고쳐지는가?

**예.** 위 표의 3개 문장(GOAL 2건 + QUESTION 3건, 문장 자체는 3개지만
검사 대상은 5건) 전부 수정 후 더 이상 Goal/Open Question으로 잘못
뽑히지 않는다.

### Regression 확인 (직접 실행)

- 순수 긍정형(`"검토가 필요하다."`, `"확인이 필요하다."`, `"판단이
  필요하다."`) — 3개 마커 모두 Goal/Open Question으로 여전히 정상
  매칭됨.
- MVP-0010이 의도적으로 허용한 Goal/Open Question 중복(한 문장이
  Goal이자 Open Question인 경우, 예: "...검토가 필요하다") — 재실행으로
  여전히 정상 동작함을 확인. 이번 수정은 그 의도적 결정을 건드리지
  않았다.
- MVP-0018(`"필요하다"` ← `"불필요하다"`), MVP-0019/0020(RISK_MARKERS
  7개 부정형) — 재실행으로 모두 여전히 정상 동작함을 재확인.
- 기존 테스트: `development-hq/mvp/tests/test_mvp_0001.py` 3건 통과.

### 실제 Engine 실행

`call_engine()`을 직접 실행해 재확인했다(`REQUIREMENT_ANALYSIS:test`).
MVP-0014~0020에서 이미 기록한 것과 동일하게, 실제 Claude CLI가 자유
형식 응답을 반환하고 `_extract_goal()`/`_extract_marked_sentences()`를
포함한 rule-based Capability Logic 경로는 호출되지 않는다. 이번
변경으로 새로 달라진 사실은 없다.

## 범위 밖 (이번 구현에서 하지 않은 것)

- `"해야 한다"`의 부정형 — 재현 시도했으나 실제 오탐이 없어 등록하지
  않았다(위 "발견한 문제" 참고).
- OUT_OF_SCOPE_MARKERS(`"않는다"`/`"제외"`/`"범위 밖"`/`"아니다"`)의
  부정형 점검 — 이번에 실측하지 않았다. `"않는다"` 마커 자체가 매우
  광범위해(임의의 부정 서술어와 겹침) 개별 부정형 등록으로 해결되지
  않을 가능성이 있어, 다음에 다룰 때는 재현 결과에 따라 Stop이 필요할
  수도 있다.
- 등록한 부정형 이외의 다른 활용형(과거형 등) — 실측하지 않았다.
- `call_engine()`의 dispatch 방식 변경 — 하지 않았다.
