# MVP-0020 Observation

## 목적

MVP-0019 Observation의 "범위 밖"에 남긴 항목("RISK_MARKERS의 나머지
항목(`실패`/`오류`/`위험`/`왜곡`/`결함`/`누락`)이 각자의 부정형 안에서
걸릴 가능성 — 이번에 실측으로 재현하지 않았으므로 다루지 않았다")을
한 번에 실측·수정한다. MVP-0018/0019가 만든 기존
`NEGATED_MARKER_EXCEPTIONS`/`_contains_marker` 방식만 재사용하고, 새
메커니즘은 만들지 않는다.

## 발견한 문제 (실제 실행으로 6개 마커 전수 재현)

각 마커에 대해 자연스러운 부정형 문장 2개씩(`"{마커}하지/되지
않는다"` 계열, `"{마커} 없이"`/`"{마커}이/가 없다"` 계열)을 직접
실행해 12건 모두 오탐임을 확인했다:

| 마커 | 오탐 문장 | 수정 전 결과 |
|---|---|---|
| 실패 | "이 프로세스는 실패하지 않는다." | Risk로 잘못 뽑힘 |
| 실패 | "실패 없이 완료되었다." | Risk로 잘못 뽑힘 |
| 오류 | "오류가 없다." | Risk로 잘못 뽑힘 |
| 오류 | "오류 없이 실행되었다." | Risk로 잘못 뽑힘 |
| 위험 | "위험하지 않다." | Risk로 잘못 뽑힘 |
| 위험 | "위험 없이 안전하게 처리된다." | Risk로 잘못 뽑힘 |
| 왜곡 | "왜곡되지 않는다." | Risk로 잘못 뽑힘 |
| 왜곡 | "왜곡 없이 그대로 전달된다." | Risk로 잘못 뽑힘 |
| 결함 | "결함이 없다." | Risk로 잘못 뽑힘 |
| 결함 | "결함 없이 동작한다." | Risk로 잘못 뽑힘 |
| 누락 | "누락되지 않는다." | Risk로 잘못 뽑힘 |
| 누락 | "누락 없이 전달된다." | Risk로 잘못 뽑힘 |

12건 모두 MVP-0018/0019와 정확히 같은 유형 — 마커가 정반대 의미의
부정형 문구 안에 부분 문자열로 걸린다.

## 변경 파일

- `development-hq/mvp/engine.py`
  - `NEGATED_MARKER_EXCEPTIONS`에 6개 마커 각각 실제로 재현된 부정형
    2개씩(총 12개 문구)을 추가했다. 새 키/새 함수/새 메커니즘은
    추가하지 않았다 — MVP-0018이 만든 구조 그대로 확장만 했다.
    ```python
    "실패": ("실패하지 않는다", "실패 없이"),
    "오류": ("오류가 없다", "오류 없이"),
    "위험": ("위험하지 않다", "위험 없이"),
    "왜곡": ("왜곡되지 않는다", "왜곡 없이"),
    "결함": ("결함이 없다", "결함 없이"),
    "누락": ("누락되지 않는다", "누락 없이"),
    ```

## 관찰 결과

### 12건 모두 고쳐지는가?

**예.** 위 표의 12개 문장 전부, 수정 후 `_extract_marked_sentences()`가
Risk로 뽑지 않는다(`- none` fallback으로 확인).

### Regression 확인 (직접 실행)

- 6개 마커 각각의 순수 긍정형(`"이 프로세스는 실패했다."`, `"오류가
  발생했다."`, `"위험이 있다."`, `"데이터가 왜곡되었다."`, `"결함이
  발견되었다."`, `"항목이 누락되었다."`) — 전부 여전히 정상적으로
  Risk로 매칭됨.
- 부정형 + 긍정형이 같은 Issue 안에 섞인 경우(`"실패 없이 완료되었다.
  다른 부분은 실패했다."`) — 부정형은 제외되고 긍정형만 정확히
  Risk로 선택됨.
- MVP-0018(`"필요하다"` ← `"불필요하다"`), MVP-0019(`"문제"` ←
  `"문제없다"`)의 기존 수정 — 재실행으로 여전히 정상 동작함을
  재확인.
- 기존 테스트: `development-hq/mvp/tests/test_mvp_0001.py` 3건 통과.

### 실제 Engine 실행

`call_engine()`을 직접 실행해 재확인했다(`REQUIREMENT_ANALYSIS:test`).
MVP-0014~0019에서 이미 기록한 것과 동일하게, 실제 Claude CLI가 자유
형식 응답을 반환하고 `_extract_marked_sentences()`를 포함한 rule-based
Capability Logic 경로는 호출되지 않는다. 이번 변경으로 새로 달라진
사실은 없다.

## 범위 밖 (이번 구현에서 하지 않은 것)

- 등록한 부정형 이외의 다른 활용형(과거형 `"실패하지 않았다"`, 관형형
  `"실패하지 않은"` 등) — 이번에 실측으로 재현하지 않았으므로 등록하지
  않았다.
- OUT_OF_SCOPE_MARKERS(`"않는다"`/`"제외"`/`"범위 밖"`/`"아니다"`)나
  GOAL_MARKERS의 나머지 항목(`"해야 한다"`/`"검토가 필요"`/`"확인이
  필요"`)의 부정형 점검 — 이번에 실측하지 않았다.
- 마커 매칭을 형태소 분석기 등 실제 NLP 파이프라인으로 교체하거나,
  `NEGATED_MARKER_EXCEPTIONS`를 정규식·규칙 엔진으로 일반화하는 것 —
  하지 않았다. 문자열 등록 방식 그대로 유지했다.
- `call_engine()`의 dispatch 방식 변경 — 하지 않았다.
