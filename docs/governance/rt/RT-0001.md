# RT-0001: Re-evaluation Trigger (ADC-0001 후속)

## 목적

ADC-0001에서 "Keep in MVP"로 판단된 4개 Kernel Extraction Candidate가 언제
다시 RFC 대상으로 올라오는지를 정의한다.

이 문서는 Architecture를 설계하지 않는다. Kernel을 설계하거나 구현하지
않는다. 관찰 가능하고 측정 가능한 재평가 조건(Trigger)만 정의한다.

---

## Candidate 1. Task Dispatcher

### Current Decision

Keep in MVP

### Re-evaluation Trigger

Workflow Branch 발생 (Task 흐름에 조건 분기·재시도·병렬 실행이 실제로
구현됨), 또는 하드코딩된 Task 호출 체인 수 ≥ 2 (Task Dispatcher가 서로
다른 Workflow에서 각각 하드코딩된 형태로 2회 이상 반복 구현됨)

### Trigger Rationale

ADC-0001의 Decision Rationale은 "MVP-0001에서 관찰된 유일한 사례(단일 선형
2-Task Workflow)"에서만 근거를 얻었다. 분기가 실제로 구현되거나, 동일한
하드코딩 패턴이 두 번째 Workflow에서 반복되는 순간, 그 근거의 전제(단일
사례)가 더 이상 성립하지 않는다.

---

## Candidate 2. Engine Gateway

### Current Decision

~~Keep in MVP~~ → **Trigger 발동 확정, Multi-Engine으로 전환됨**
(`docs/architecture/core/ADC-0039-multi-engine-re-evaluation.md` Amendment,
`docs/architecture/core/ADR-0024-multi-engine-architecture-adoption.md`).
아래 "Keep in MVP" 판정과 Trigger 원문은 삭제하지 않고 역사적 기록으로
보존한다 — 이 Trigger가 실제로 언제·왜 발동했는지 설명하는 근거이기
때문이다.

### Re-evaluation Trigger

Engine 수 ≥ 2 (두 번째 Engine이 실제로 추가되어 `call_engine()` 호출 지점이
둘 이상의 서로 다른 Engine을 대상으로 하게 됨)

**[발동 확정, ADR-0024]**: `chatgpt_engine.py`(신규)와 `engine.py`
(Claude Code)가 각각 다른 호출부에서 실제로 사용되며, 이 Trigger 원문
그대로를 충족한다. Engine Gateway(Central Router)는 여전히 만들지
않았다 — 발동한 것은 "Engine 수 ≥ 2" 조건뿐이며, `IMPLEMENTATION_
RULES.md` 15행(Gateway 추상화 금지)은 `ADR-0024`가 Scoped 예외로
확인한 범위 밖에서 그대로 유효하다.

### Trigger Rationale

ADC-0001의 Decision Rationale은 "MVP-0001에서 관찰된 범위(단일 Engine)"에서만
근거를 얻었다. 두 번째 Engine이 실제로 추가되는 순간, 그 전제(단일 Engine)가
더 이상 성립하지 않는다.

## Candidate 3. Agent Registry

### Current Decision

Keep in MVP

### Re-evaluation Trigger

HQ 수 ≥ 2 (두 번째 HQ가 실제로 구현되어 Agent-Capability 매핑을 HQ 경계를
넘어 조회해야 하는 상황이 발생함), 또는 Registry 중복 관리 발생 (동일한
Agent-Capability 정보를 두 곳 이상의 딕셔너리·파일에서 수동으로 각각
관리하게 됨)

### Trigger Rationale

ADC-0001의 Decision Rationale은 "MVP-0001에서 관찰된 범위(단일 HQ, 2개
Agent)"에서만 근거를 얻었다. 두 번째 HQ가 실제로 구현되거나 매핑이 중복
관리되는 순간, 그 전제(단일 HQ, 단일 매핑 소스)가 더 이상 성립하지 않는다.

---

## Candidate 4. Context 전달 메커니즘

### Current Decision

Keep in MVP

### Re-evaluation Trigger

Context 전달 경로 ≥ 2 (동일 Workflow 실행 내에서 Task 간 데이터를 전달하는
경로가 지역 변수 전달 하나 외에 실제로 하나 더 생김)

### Trigger Rationale

ADC-0001의 Decision Rationale은 "MVP-0001에서 실제로 실행된 유일한 경로(단일
성공 경로)"에서만 근거를 얻었다. 전달 경로가 둘 이상 실제로 생기는 순간,
그 전제(단일 경로)가 더 이상 성립하지 않는다.

## Self Review Checklist

- [x] Trigger가 실제 관찰 가능한가 — 모두 "실제로 추가됨/구현됨/발생함"
      형태의 사건으로 서술했다.
- [x] Trigger가 수치 또는 사건으로 표현되는가 — Engine 수 ≥ 2, HQ 수 ≥ 2,
      Workflow Branch 발생, Registry 중복 관리 발생, Context 전달 경로 ≥ 2.
- [x] 새로운 Architecture를 만들지 않았는가 — 새 Layer/Component/Service/
      Runtime/Registry/Scheduler/Policy/Memory/Kernel 기능 없음.
- [x] 구현 방법을 설명하지 않았는가 — Trigger와 그 발생 시 ADC-0001 근거의
      전제가 깨진다는 설명만 있고, 대체 메커니즘 설계는 없음.
- [x] Candidate가 정확히 4개인가 — Task Dispatcher, Engine Gateway, Agent
      Registry, Context 전달 메커니즘 4개만 다룸.
- [x] Architecture Drift가 없는가 — 없음.
- [x] Kernel Leak가 없는가 — 없음.
