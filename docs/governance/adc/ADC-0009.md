# ADC-0009: "Implementation Freedom" 원칙 도입 여부 판단 (RFC-0011 후속)

## 목적

RFC-0011(Development HQ 수준, `docs/decisions/rfc/
RFC-0011-implementation-freedom-principle.md`)이 제기한 Q-1/Q-2
Boundary Question을 판단한다.

근거는 RFC-0011 원문과 그것이 인용하는 `docs/governance/README.md`,
`ADR-0010`, `hqs/development/CONSTITUTION.md`,
`hqs/development/IMPLEMENTATION_RULES.md`,
`docs/architecture/core/ADR-0016-omniroute-thin-caller-freeze-scoped-relaxation.md`,
`docs/architecture/core/ADC-0027-omniroute-model-routing-engine-adapter-conditional-adoption.md`로
한정한다. 이 문서 자체는 새로운 조사를 하지 않는다.

이 ADC는 ADC-0008과 같은 성격이다 — Kernel 승격 여부가 아니라
**Governance 절차 자체에 대한 서술을 저장소 문서에 추가할지 여부**를
묻는다. "Accept / Reject / Scoped Accept / Defer" 중 하나로 판단한다.

## 판단 대상에서 제외

- `docs/governance/README.md`의 실제 본문 수정 — 이 ADC는 채택 여부와
  Scope만 판단하며, 실제 반영은 후속 ADR 대상이다(RFC-0011 §5).
- `hqs/development/CONSTITUTION.md`의 Architecture Freeze 목록 개정 —
  이 ADC가 긴장 관계를 확인하더라도 그 자체를 재평가하거나 목록을
  수정하지 않는다(사용자 지시 6·9번).
- LangGraph, Graphify를 포함한 어떤 구체적 기술의 채택 여부 판단.

---

## 판단 1 (Q-1). 5개 명제 중 최소 추가가 필요한 부분

### Evidence

RFC-0011 §1 대조표 — 명제 4("Deferred/Not Accepted ≠ Forbidden")는
`docs/governance/README.md`에 이미 문구 단위로 존재한다. 명제 1·2·3은
어떤 형태로도 존재하지 않는다. 명제 5는 "Freeze는 실제 Invariant에만
사용한다"는 형태로 **Freeze라는 한 절차에만 부분적으로** 존재하며,
Governance 절차 전체(RFC 개설, ADC 판단 등)에 대한 일반 원칙으로는
서술되어 있지 않다.

### Constraint / Boundary

- 사용자 지시 4번: 이미 포함된 것은 중복 문구를 만들지 않는다 —
  명제 4를 다시 옮겨 적지 않는다.
- 사용자 지시 5번: 명시적 선언이 필요하다고 판단되는 경우에만 최소
  변경안을 만든다 — 전체 5개 명제를 그대로 옮기는 것은 최소 변경이
  아니다.
- 새로 추가하는 문구도 §2(RFC 적용 범위, `ADR-0010`)나 §3(Tier/Freeze/
  Deferred)이 이미 정한 절차·범위를 재정의해서는 안 된다(선례:
  `ADR-0010`이 자신도 유사한 이유로 RFC 적용 범위를 스스로 재정의하지
  않고 기존 정의를 참조하도록 정정한 바 있다).

### Options

- (a) 5개 명제 원문 전체를 새 절로 추가한다(명제 4 중복 포함).
- (b) 명제 1·2·3을 하나의 원칙 문장으로 압축하고, 명제 5는 기존
  "Freeze는 실제 Invariant에만" 문구를 Governance 전체로 일반화하는
  한 문장을 추가한다. 명제 4는 추가하지 않고 기존 문구를 그대로
  둔다.
- (c) 추가하지 않는다.

### Recommendation

(b). (a)는 이미 존재하는 명제 4를 중복 서술하게 되어 사용자 지시
4번을 위반한다. (c)는 CONSTITUTION.md의 "Evidence 없이는 개발하지
않는다"는 절대형 표현과 실제로 긴장 관계에 있는 원칙(RFC-0011 §1의
"미포함"·"부분 포함" 항목)을 문서화하지 않은 채로 남겨, 향후 같은
질문이 반복될 위험이 있다(Governance v2 P17류 반복 패턴).

### Final Judgment

**Scoped Accept (b).** `docs/governance/README.md`의 "Outcome-Oriented
Governance Model" 절에 다음 두 항목을 추가한다 — 정확한 문구는 후속
ADR이 확정한다.

1. Evidence 부재 자체는 구현 기술 선택을 금지하는 사전 허가 조건이
   아니라는 것, 그리고 Goal·Invariant를 만족하는 범위에서 구현
   기술을 자유롭게 선택할 수 있다는 것(명제 1·2·3의 압축).
2. "Freeze는 실제 Invariant에만 사용한다"는 기존 원칙을 Freeze만이
   아니라 Governance 판단 전반(RFC 개설, ADC 판단 포함)으로
   일반화한 것(명제 5의 확장) — 단, 이 일반화가 기존에 이미 확정된
   개별 Freeze/ADC/RFC 판단(예: `CONSTITUTION.md`의 목록, 기존 Not
   Accepted RFC들)을 소급 변경하지 않는다는 단서를 명시한다(`ADR-0010`
   §3의 소급 미적용 선례와 동일 형식).

명제 4는 추가하지 않는다 — 기존 문구를 그대로 둔다.

## 판단 2 (Q-2). `CONSTITUTION.md` Architecture Freeze 목록과의 긴장 관계

### Evidence

- `CONSTITUTION.md`는 Runtime/Pipeline Generalization/Task Dispatcher
  Generalization/Stage Runner/Event Bus/Scheduler/Multi-Agent
  Runtime/Engine Adapter/Model Routing을 "충분한 Evidence가 나올
  때까지 동결"하고 "반복된 실전 Evidence 없이는 개발하지 않는다"고
  선언한다. 이 항목들은 `ADR-0010` §3이 정의한 Freeze 대상(Security/
  Data Integrity/Contract 호환성/되돌릴 수 없는 파괴적 동작/
  Compliance) 중 어디에도 직접 해당하지 않는다 — 조기 일반화 방지가
  근거다(`BASELINE.md` §10/§11, `GOVERNANCE-REVIEW-0001` §5의 6개
  근거가 "여전히 유효"하다고 반복 확인됨).
- 그러나 이 목록 중 `Engine Adapter`·`Model Routing` 두 항목은 이미
  `ADR-0016`(Scoped 예외 선언) → `ADC-0027`(Conditional Accept,
  OmniRoute 실제 안전 설정 실증 Evidence 근거)을 거쳐 **Governance
  절차로 조건부 해제**된 선례가 실재한다. 즉 이 Freeze는 "시도 자체를
  영구 봉쇄"하는 것이 아니라 "Evidence가 쌓이면 RFC→ADC→ADR 절차로
  재평가 가능한 동결"로 이미 실제 운용되고 있다.

### Constraint / Boundary

- 이 ADC는 `CONSTITUTION.md`를 재평가하거나 수정할 권한이 없다 —
  `hqs/development/`는 HANDOVER.md가 명시한 별도 Frozen Starter Kit
  이며, 그 자체의 재평가는 이 Governance 트랙(Jarvis OS Governance
  Charter)이 아니라 Development HQ 수준 절차(RFC-0005 Development HQ
  Boundary 트랙 등)를 통해서만 열려야 한다.
- 사용자 지시 9번: LangGraph/Graphify 등 기존 Deferred/Not Adopted
  상태를 자동으로 바꾸지 않는다 — Engine Adapter/Model Routing의
  기존 Scoped 해제도 다시 논의하지 않는다.

### Options

- (a) 긴장 관계가 실재한다고 확정하고, `CONSTITUTION.md`를 즉시
  개정 대상으로 지정한다.
- (b) 긴장 관계의 **존재 자체는 인정**하되(문면상 "Evidence 없이는
  개발하지 않는다"는 절대형 표현), `CONSTITUTION.md`가 실제로는
  이미 Evidence 기반 재평가 절차(ADR-0016 선례)로 운용되고 있다는
  점에서 **명제 1~5와 실질적으로 상충하지 않는다**고 보되, 문면
  표현과 실제 운용 사이의 불일치는 "후속 재평가 후보"로만 기록하고
  이번에 개정하지 않는다.
- (c) 아무 관계도 없다고 판단하고 기록조차 하지 않는다.

### Recommendation

(b). (a)는 사용자 지시 6·9번을 위반한다(Freeze/Deferred 상태를 이
작업에서 변경하지 않는다). (c)는 RFC-0011이 이미 확인한 문면상
불일치(§Q2 Evidence)를 근거 없이 덮어버리는 것이며, Governance v2
P17("반복되는 예외/충돌은 상위 Governance 재평가 신호")의 관찰
누적 원칙과 맞지 않는다.

### Final Judgment

**Scoped Accept (b), 개정 없음.** `CONSTITUTION.md`의 "반복된 실전
Evidence 없이는 개발하지 않는다"는 문면 표현은, "Implementation
Freedom" 원칙과 완전히 같은 어휘를 쓰지 않지만 실제 운용(ADR-0016
선례)에서는 상충하지 않는다고 판단한다. 이 ADC는 다음만 기록하고
개정하지 않는다.

> **후속 재평가 후보(이 ADC가 결정하지 않음)**: `CONSTITUTION.md`의
> Architecture Freeze 목록 문면이 "Evidence 없이는 시도 자체를 금지"로
> 오독될 수 있다는 점은, 향후 Development HQ 수준 RFC가 열릴 경우
> 검토할 후보로 남긴다. 이 ADC와 후속 ADR은 `CONSTITUTION.md`를
> 수정하지 않는다.

## 종합 Decision

**Scoped Accept (Q-1 Scoped Accept (b) / Q-2 Scoped Accept (b),
개정 없음).**

| 대상 | Governance 변경 필요 | 처리 |
|---|---|---|
| Q-1 명제 1·2·3 압축 원칙 추가 | 필요 | 후속 ADR에서 `docs/governance/README.md` "Outcome-Oriented Governance Model" 절에 반영 |
| Q-1 명제 5의 Freeze→Governance 전반 일반화 | 필요 | 후속 ADR에서 동일 절에 반영, 소급 미적용 단서 포함 |
| Q-1 명제 4 재서술 | 불필요(이미 존재) | 처리 없음 |
| Q-2 `CONSTITUTION.md` 개정 | 불필요(이 작업 범위 아님) | 후속 재평가 후보로만 기록 — Architecture/Contract 변경 후보 보고, 구현하지 않음(사용자 지시 11번) |
| `docs/governance/README.md` 등 실제 본문 수정 | (ADC 확정 이후) | 이 ADC는 수행하지 않음 — 후속 ADR이 유일한 반영 경로 |

Baseline 반영 정확한 문구·배치, ADR 채번은 후속 ADR 단계에서
확정한다(이 ADC가 결정하지 않음). RFC-0011의 Status/Decision 절은 이
ADC의 결과를 반영해 Resolved로 갱신하고, `docs/decisions/rfc/
README.md` 등록 표의 후속 ADC 칸에 이 문서를 연결한다.

**후속 ADR**: `docs/decisions/adr/
ADR-0011-implementation-freedom-principle-baseline.md`. Status는
Proposed(사용자 승인 대기)이며, 승인 전까지 `docs/governance/
README.md`는 이 ADC·해당 ADR 어느 것으로도 수정되지 않는다.
