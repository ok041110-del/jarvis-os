# Evidence — MSFT Stock Dogfooding (실행 1회차) + AAPL/NVDA/MSFT 3사 비교

PRD v1.2 8장 관찰 항목 기준. AAPL/NVDA EVIDENCE.md와 같은 형식이며, 이 문서는
추가로 3사 종합 비교와 이번 실행에서 특별히 요청된 질문에 답한다.

## 업무 (Task)

- 9단계 파이프라인이 이번에도 수동 개입 없이 완주됐다. 3사 모두 동일한
  구조(5개 독립 분석 → Bull/Bear → Synthesis → Report)로 처리 가능했다 —
  기업마다 재무 구조가 크게 다름에도(Apple: 하드웨어 중심, NVIDIA: 단일
  세그먼트 초집중, Microsoft: 멀티 세그먼트+규제 리스크) Task 분해 자체는
  바뀌지 않았다.

## 역할 (Role)

- 5개 역할이 3번째로도 서로 겹치지 않는 관점을 유지했다. 이번 실행에서
  특히 Industry Analyst와 News/Event Analyst의 결과가 Synthesis 단계에서
  서로 강하게 연결됐다(Azure의 번들링/통합 전략이 동시에 "경쟁 우위"이자
  "FTC 조사 대상"이라는 이중적 사실 — `synthesis.md` 24~25행) — 개별
  역할은 자기 영역만 보고 반환했지만, Synthesis가 두 역할의 산출물을
  실제로 교차 연결해 개별 분석 어디에도 없던 통찰을 만들어냈다.

## 협업 (Collaboration) — "Bull/Bear가 계속 유용한가?"

- 3번째 실행에서도 유용성이 확인됐고, 오히려 이번이 가장 뚜렷한 사례다:
  Bull은 Azure 번들링을 "우위"로, Bear는 같은 사실을 "FTC 조사 대상"으로
  읽었고, Synthesis가 "이 모순은 봐주기가 아니라 실제로 동시에 참인
  상태"라고 명시적으로 정리했다. Bull/Bear 대립이 단순 찬반이 아니라
  실제로 상충하는 해석의 구조를 드러내는 데 기여했다.
- Task 간 Context는 이번에도 in-memory 변수(문자열 결합)만으로 충분했다 —
  3번째 실행까지 예외가 없었다.

## 시스템 (System)

- Stop Trigger 미발동. Kernel/Registry/Scheduler 확장 불필요함이 3번째로
  재확인됐다.
- **"출력 언어 불일치가 다시 발생하는가?" — 발생했고, 이번엔 더 세분화된
  형태로 관찰됨.** AAPL은 실행 전체가 한국어, NVDA는 실행 전체가 영어였는데,
  MSFT는 **같은 실행 안에서 Capability별로 언어가 갈렸다**:
  Fundamental/Technical은 영어, Industry/News-Event는 한국어, Sentiment는
  영어 제목 + 한국어 본문(파일 하나 내부에서도 혼재). Bull/Bear/Synthesis/
  Final Report는 전부 영어였는데, Final Report가 한국어로 온 Industry/
  News-Event 내용까지 전부 영어로 자연스럽게 재통합했다 — 즉 Report
  Writer 단계가 사실상 번역/정규화 역할도 겸했다. 이는 산출물 품질을
  해치지 않았지만(최종 문서는 완전히 일관됨), 언어가 **실행 단위가 아니라
  개별 Engine 호출 단위로 독립적으로 결정된다**는 것을 보여준다 — 3회
  실행 중 3가지 다른 패턴(전체 한국어/전체 영어/혼재)이 나왔으므로 명백히
  비결정적이다.
- **"병렬 실행의 실제 필요성이 발생하는가?" — 발생하지 않았다.** 9회 호출
  누적 3회 실행(27회 `call_engine()` 호출) 전부 순차 실행으로 성능 문제
  없이 완료됐다. 병렬화가 필요하다는 근거는 3번째 실행까지 나타나지 않았다.

| 새 Kernel/Registry/Scheduler 필요 | 없음 | 없음 | 없음 | **3/3 반복** |

## 공통 역할을 별도 Stock 조직(Team)으로 승격할 만큼 반복성이 생겼는가

PRD 5장 기준("실제 업무에서 반복되는 전문 역할과 협업이 확인될 때만 Team/
Role/Agent 후보로 승격")으로 판단하면:

- **찬성 근거**: 5개 분석 역할 + Bull/Bear + Synthesis + Report라는 9단계
  구조가 3개의 서로 다른 산업(소비자 하드웨어/AI 반도체/기업용
  소프트웨어+클라우드)에서 **구조 변경 없이** 3/3 성공했다. 이는 "우연히
  한 번 맞았다"가 아니라 반복되는 패턴이라는 근거로 충분히 강하다.
- **반대/유보 근거**: (1) 3개 기업 모두 미국 대형 기술주로 산업 다양성이
  제한적이다(금융/헬스케어/소비재/신흥시장 기업 등은 미검증). (2) 이번
  PRD의 범위는 "Team/Role/Agent 후보로 승격"이지 "지금 이 세션이 그
  구조를 코드/문서로 만든다"가 아니다 — PRD 11장이 Investment HQ
  Architecture를 이 단계에서 선행 설계하지 말라고 명시한다. (3) Division/
  Team은 Development HQ Baseline상 "선택적 내부 관례"이며 Kernel이 알
  필요가 없는 계층이므로 RFC 없이 결정 가능한 사안이지만, 그 결정 자체는
  이 Dogfooding 세션이 임의로 내리지 않고 사용자에게 후보로 보고하는 것이
  맞다.

**결론(권고, 결정 아님)**: 반복성 자체는 "Stock Team" 후보로 승격을
검토할 만큼 쌓였다고 판단한다. 다만 실제 승격 여부와 시점은 PRD 10장의
확장 순서(Stock → ETF → Dividend Stock)와 사용자의 판단에 맡기며, 이
세션이 임의로 조직 구조를 코드/디렉터리로 확정하지 않는다.
