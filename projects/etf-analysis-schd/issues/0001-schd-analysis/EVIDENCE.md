# Evidence — SCHD ETF Dogfooding (실행 1회차, ETF 두 번째) — QQQ 반복성 검증

PRD v1.2 관찰 항목 기준, `projects/etf-analysis-qqq/issues/0001-qqq-analysis/EVIDENCE.md`
와 동일한 형식. 이번 실행의 목적은 QQQ(기술 성장주, 낮은 배당)에서 확인된
ETF 업무 구조가 성격이 완전히 다른 ETF(SCHD, 배당/가치주 중심)에서도
반복되는지 검증하는 것이다.

## 업무 (Task)

- 11단계 파이프라인이 수동 개입 없이 완주됐다(QQQ와 동일한 구조:
  7개 분석 → Bull/Bear → Synthesis → Final Report).
- `call_log.json` 실측: 11회 호출 합계 400.7초 — QQQ(402.8초)와
  **거의 동일**했다. 개별 단계별 소요 시간은 QQQ와 다르게 분포됐지만
  (아래 표), 전체 파이프라인 소요 시간 자체는 두 ETF에서 놀랍도록
  안정적이었다.

## ETF 고유 역할 반복 여부

Composition/Index, Cost/Tracking, Distribution 3개 역할(QQQ에서 Stock에
대응 항목이 없다고 확인된 역할)이 SCHD에서도 그대로 필요했고, 동일한
지시문 패턴으로 실제로 유의미한 산출물을 만들어냈다:

- **Composition/Index Analyst**: QQQ의 "modified market-cap 가중 +
  방법론 변경"과 달리, SCHD는 "10년 연속 배당 이력 기준 4단계
  스크리닝 + 연 1회 reconstitution"이라는 완전히 다른 방법론을
  다뤘다 — 역할 이름과 함수 시그니처는 동일하게 재사용됐지만, 실제
  분석 내용은 ETF마다 완전히 달랐다(당연한 결과이나, "같은 역할이
  다른 내용을 다룬다"는 것을 실측으로 확인).
- **Cost/Tracking Analyst**: QQQ와 동일하게 추적오차 수치 부재를
  스스로 명시했다. 추가로 SCHD 고유의 "reconstitution발 특별 분배금
  $0.8241/주가 실질 비용 요소일 수 있다"는 새로운 유형의 비용 이슈를
  스스로 식별했다 — Stock/QQQ 어디에도 없던 관찰이 ETF 고유 개념
  (reconstitution 관련 세금·분배 효과) 안에서 두 번째 실행에서 처음
  나타남.
- **Distribution Analyst**: QQQ(배당수익률 0.42%)와 대조적으로 SCHD
  (배당수익률 ~3%)는 3개 소스 간 수익률 수치 불일치(3.06%/2.95%/3.30%)
  를 스스로 지적했다 — QQQ의 목표주가 불일치 패턴과 성격이 같은
  "복수 소스 간 정량 지표 불일치 자기인정"이 Distribution 역할에서도
  재현됨.

**결론: ETF 고유 3개 역할이 2/2(QQQ, SCHD) 반복 확인됐다.** 1회 실행
(QQQ)에서만 관찰됐을 때보다 근거가 명확히 강화됐다 — 서로 다른 성격의
펀드(성장주 vs 배당주)에서도 동일한 역할 분리가 그대로 유효했다.

## Bull/Bear/Synthesis/Final Report 구조 재검증

- Synthesis가 이번에도 "**두 진영 사이에 실제 사실 충돌은 없다**"고
  명시했다 — QQQ Synthesis("no factual dispute")와 사실상 동일한
  결론이다. 이로써 "동일 사실, 대립적 해석만 존재" 패턴이 JPM(Stock)→
  QQQ(ETF)→SCHD(ETF) 3회 연속 관찰됐다 — Stock/ETF 도메인을 넘나드는
  반복이라는 점에서 이전보다 근거가 더 강해졌다.
- Bull/Bear가 갈리는 지점도 QQQ와 동일한 유형이었다: 같은 수치(베타
  0.56, 섹터 편중, reconstitution 발생 사실)를 두고 "낮은 변동성/
  방어적 우위"(Bull) vs "구조적 약점/불안정성"(Bear)으로 정반대
  해석했다 — QQQ의 "집중도를 우위로 볼지 리스크로 볼지" 갈림과 동일한
  구조.
- **Macro Analyst가 이번에는 QQQ의 Macro 자료를 명시적으로 교차
  언급했다**: SCHD `raw_data.md`에 "이는 QQQ의 Macro 자료에서 나온
  2026-06-17 FOMC 정보와 시점이 다르고 상호 정합성이 검증되지 않음"
  이라는 문구를 의도적으로 포함시켰는데, Macro Analyst가 이를 그대로
  받아 "별도로 소싱된 QQQ용 매파적 dot-plot 자료와의 정합성이 검증되지
  않았다"고 정확히 반영했다. 이는 **실제 Capability 공유는 아니지만
  (각 프로젝트가 독립적으로 raw_data.md를 소유), 서로 다른 ETF 실행
  간 Context 참조가 텍스트 수준에서 가능함을 보여준 최초 사례**다 —
  다만 이번에는 이 세션이 raw_data.md 작성 시 의도적으로 넣은 문구이지,
  Capability가 스스로 다른 프로젝트 파일을 조회한 것이 아니다(Engine은
  WebFetch/파일 접근이 차단되어 있으므로 그럴 수 없음).

## Context 규모/실행시간 — QQQ 대비 실측 비교

| 항목 | QQQ | SCHD | 비고 |
|---|---|---|---|
| 분석당 입력 | 872~1,180자 | 911~1,171자 | 거의 동일 |
| 분석당 출력 | 1,484~4,031자 | 3,718~4,047자 | SCHD가 더 크고 균일함 |
| Bull/Bear 입력 | 20,155자 | 27,676자(+37%) | SCHD 분석 출력이 전반적으로 더 길었기 때문 |
| Bear 소요시간 | 43.9초 | 62.4초(+42%) | 입력 증가와 대체로 비례 |
| Synthesis 입력 | 15,315자 | 17,836자 | |
| Final Report 입력 | 41,567자(QQQ가 더 큼) | 51,306자(SCHD가 더 큼) | SCHD가 오히려 더 큼 |
| Final Report 출력 | 19,709자 | 14,803자(더 작음) | **입력은 SCHD가 크지만 출력은 더 작음** |
| Final Report 소요시간 | 133.5초 | **60.3초(QQQ의 45%)** | **입력 크기와 반대 방향으로 움직임** |
| 11단계 합계 | 402.8초 | 400.7초 | **거의 동일** |

**가장 중요한 발견**: QQQ EVIDENCE.md는 "Final Report 소요시간이 입력
크기보다 출력 길이와 더 강하게 연관되는 것으로 보인다"는 가설을 추세
관찰로 기록했었다. 이번 SCHD 실행이 그 가설을 **강하게 뒷받침**한다 —
입력은 SCHD가 더 컸음에도(51,306>41,567) 출력이 더 작았고(14,803<19,709),
소요시간도 더 짧았다(60.3<133.5). 반면 11단계 전체 합계 소요시간은 두
ETF에서 거의 동일(402.8초 vs 400.7초)했다 — 개별 단계의 편차는 있지만
파이프라인 총 소요시간 자체는 두 번의 실행에서 안정적이었다.

## Stock과 공통으로 사용할 수 있는 역할의 실제 반복 여부

**여전히 없다.** SCHD도 Stock의 5개 분석 역할(Fundamental/Technical/
Industry/News-Event/Sentiment)을 재사용하지 않았다 — QQQ와 마찬가지로
처음부터 ETF 전용 7개 역할로 새로 작성했다. Stock-ETF 간 실제 Capability
공유는 이번에도 시도되지 않았고 필요도 관찰되지 않았다.

## Cache 필요성

QQQ와 동일하게 발생하지 않았다. 11개 호출 전부 서로 다른 지시문·데이터
였다.

## 병렬 실행 필요성

**여전히 미검증이다.** 이번에 2번째 ETF를 다뤘지만, QQQ와 SCHD는
서로 다른 세션/실행에서 순차적으로 처리됐을 뿐 "여러 ETF를 동시에
배치 처리해야 하는 실제 업무"는 이번에도 발생하지 않았다 — "다중 ETF
업무가 실제로 발생한 경우"에 해당하지 않으므로, 병렬 실행 필요성에
대한 판단을 계속 보류한다.

## 정기 데이터 갱신 — Runtime/Automation 필요성

발생하지 않았다. SCHD도 QQQ와 동일하게 1회성 수동 WebSearch 스냅샷으로
충분했다. SCHD의 연 1회 reconstitution(3월)이라는 사실이 정기 갱신의
개념적 필요성을 다시 시사했으나(QQQ의 분기 리밸런싱과 유사한 성격),
이번 실행에서 실제로 자동 갱신이 필요했던 지점은 없었다.

## 시스템 (System)

- Stop Trigger 미발동. Kernel/Registry/Scheduler 확장 불필요함이 ETF
  두 번째 실행에서도 재확인됐다.
- 데이터 불일치 자기인정 패턴이 이번에도 반복됐다: 보유종목 상위권
  구성 자체가 시점에 따라 다르게 보도된 것(에너지→헬스케어 종목
  교체)을 Holdings Analyst가 스스로 "추정이며 확정 사실 아님"이라고
  명시했다.
- 출력 언어: 이번 실행은 11개 산출물 전부가 영어였다(QQQ는 9개 영어+
  2개 한국어 혼재). 6회 누적(AAPL=한국어/NVDA=영어/MSFT=혼재/JPM=영어/
  QQQ=혼재/SCHD=영어) 기준으로도 언어 패턴은 여전히 비결정적이다.

## 새로운 요구사항이 발생했는가

- **Reconstitution발 세금/분배 효과**(Cost Analyst가 자발적으로 식별)
  — Stock에는 없고 QQQ에서도 명시적으로 드러나지 않았던 ETF 고유의
  하위 관찰. 새 Capability나 역할 분리가 필요하다는 근거는 아니며,
  기존 Cost/Tracking Analyst 역할 안에서 자연스럽게 다뤄졌다.
- **교차 ETF Context 참조**(Macro Analyst가 QQQ 자료를 인지) — 이
  세션이 raw_data.md에 의도적으로 넣은 문구에 대한 반응이며, Capability
  가 스스로 다른 프로젝트를 조회한 것이 아니다. 새 Architecture 필요를
  시사하지 않는다.
- 그 외 새로운 역할/Capability 요구는 관찰되지 않았다 — 오히려 기존
  QQQ의 7개 역할 분류가 성격이 다른 ETF에서도 변경 없이 충분했다는
  점이 이번 실행의 핵심 결론이다.

## 관찰되지 않은 것 (명시적으로 기록)

- 여러 ETF의 동시/배치 처리 — 이번에도 시도되지 않음.
- Stock-ETF 간 실제 Capability 공유 — 시도되지 않았고 필요도 없음.
- Cache/Runtime/Automation이 실제로 필요해지는 시점 — 2회 실행 모두
  나타나지 않음.
